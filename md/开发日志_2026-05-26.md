## 一、练习生成问题修复

### 1.1 题库 fallback 重复出同一题

#### 问题

- 当 LLM 生成失败或输出不符合 JSON 结构时，系统会回退到 `EXERCISE_BANK`
- 但生成接口没有把上一题传回生成节点，导致 fallback 总是取到同一题

#### 修改

- `web_app.py`
  - `/api/practice/generate` 生成练习时，把当前 session 中 `_current_exercise.source_text` 传回 Agent
- `lingua_agent/nodes.py`
  - `_pick_exercise()` 从“找第一道不相等题”改为“基于上一题顺序轮换下一题”

#### 结果

- 即使走题库 fallback，也不会重复出同一题

---

### 1.2 练习题卡出现“蹦字/像在吐 token”

#### 问题

- 用户观察到生成练习时题卡出现逐步外蹦文字的观感
- 排查后确认并非真实流式输出，而是：
  - 生成阶段前端仍持有旧题状态
  - 题目文本未统一清洗
  - 文本展示样式未强制断行/换行

#### 修改

- `lingua_agent/nodes.py`
  - 新增 `_normalize_exercise_text()`，对 `source_text` 和 `reference_translation` 做清洗
  - 去除 markdown 代码块、字段前缀、包裹引号、多余空行和解释性残留
  - 若清洗后为空，则强制回退题库
- `frontend/src/app/(steps)/practice/page.tsx`
  - 重新生成练习前先 `reset()` 当前练习状态
  - 生成中只显示 skeleton，不保留旧题文本
- `frontend/src/app/(steps)/practice/_components/SourceTextDisplay.tsx`
  - 增加 `whitespace-pre-wrap break-words`
- `frontend/src/app/(steps)/practice/_components/ReferenceReveal.tsx`
  - 同步增加 `whitespace-pre-wrap break-words`

#### 结果

- 练习题卡只显示最终确定的题目文本
- 不再暴露 LLM 中间态痕迹

## 二、诊断题逻辑重构

### 2.1 原问题

原有诊断逻辑位于 `lingua_agent/diagnosis.py`，存在以下问题：

- 默认一次生成 5 题，且按 `A1 -> A2 -> B1 -> B2` 混排
- 混合选择、填空、短翻译、改错，测试目标不纯
- fallback 题库方向不统一，例如中译俄场景下混入俄语填空
- 初始诊断体验更像杂糅考试，不像分级测评

### 2.2 修改

- `lingua_agent/diagnosis.py`
  - 删除“LLM 混合生成诊断题”主逻辑
  - 改为稳定的、同方向的、低阶短翻译题库
  - 默认返回 3 道题，难度控制为 A1/A2
- `web_app.py`
  - `DiagnosisStartRequest.question_count` 默认值从 `5` 改为 `3`

### 2.3 结果

- 初始诊断改为轻量短句翻译测评
- 出题方向统一，难度更稳
- 更适合作为门户页中的“开始学习前的测评入口”

## 六、译者能力显示与等级显示问题修复

### 6.1 问题

用户指出：

- 五维能力显示存在误导
- 例如页面上显示“语义传达 25/25”
- 但实际应表达为“当前等级内进度 / 当前等级上限”
- 同时要求参考《死亡搁浅》的成长评级逻辑

### 6.2 排查结果

- `learning.py` 中原本已有一套能力成长体系：
  - 每级 300 XP
  - 最低维度决定当前等级
  - 每 60 XP 对应一级称号进阶
- 问题不在于体系缺失，而在于：
  - `per_dim_progress` 没返回每维当前等级的上限值
  - `AbilityCard.tsx` 只显示了当前值和累计总 XP，语义不清晰

### 6.3 修改

- `lingua_agent/tools/learning.py`
  - 保留原有 `compute_ability_rank()`
  - 在 `per_dim_progress` 中新增 `cap: _XP_PER_LEVEL`
- `frontend/src/lib/utils/types.ts`
  - `DimProgress` 新增 `cap`
- `frontend/src/app/(steps)/review/_components/AbilityCard.tsx`
  - XP 条显示调整为：
    - `current_level_xp / cap`
  - 增加“当前 / 上限”文案
  - 强化工业感和仪表盘感样式

### 6.4 说明

当前仍沿用项目原先的成长体系：

- 等级：A1 / A2 / B1 / B2 / C1
- 每级 300 XP
- 每级 5 个称号阶段
- 进阶条件由最低维度控制

这与《死亡搁浅》那种“多维能力独立积累、整体等级由短板控制”的设计思路一致。
